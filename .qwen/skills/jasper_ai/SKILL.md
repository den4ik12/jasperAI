# jasper_ai

## Назначение

Скилл отвечает за локальное приложение jasper_ai: запуск, остановку и подготовку окружения для генерации печатных форм, чеков, JRXML-кода и JasperReports-шаблонов.

Используй скилл, если запрос связан с:

- печатными формами;
- печатками;
- чеками;
- HTML-макетами документов;
- JRXML;
- JasperReports;
- шаблонами отчетов;
- локальным редактором печатной формы.

## Базовые правила

Перед командами перейди в папку дистрибутива jasper_ai.

Папка дистрибутива - это папка, в которой лежат `scripts/pre-start.sh`, `scripts/start.sh` и `scripts/stop.sh`.

```text
./jasper_ai.jar
./env
./logs/jasperai.log
```

Не проверяй вручную `jasper_ai.jar`, `env`, Java или доступность логов. Это делает `scripts/pre-start.sh`.

Никогда не записывай API-ключи в:

- `src/main/resources/application.properties`;
- README;
- документацию;
- сообщения пользователю;
- историю команд.

## Ошибки скриптов

Если `pre-start.sh`, `start.sh` или `stop.sh` завершился с ошибкой, используй только эти структурированные поля:

```text
JASPERAI_ERROR_RESOLVER=...
JASPERAI_LOG_FILE=...
```

Действия:

- если есть `JASPERAI_ERROR_RESOLVER`, выполняй ровно эту инструкцию и не придумывай дополнительные действия;
- если есть `JASPERAI_LOG_FILE`, не печатай содержимое лога без отдельной просьбы;

Если `JASPERAI_ERROR_RESOLVER` просит создать или обновить `./env`, спроси у пользователя недостающий провайдер/API-ключ и не выводи ключ в чат.

## Шаблоны env

Для DeepSeek:

```bash
cat > ./env <<'EOF'
SPRING_AI_MODEL_CHAT=deepseek
DEEPSEEK_API_KEY=PASTE_USER_KEY_HERE
EOF
```

Для GigaChat:

```bash
cat > ./env <<'EOF'
SPRING_AI_MODEL_CHAT=gigachat
GIGACHAT_API_KEY=PASTE_USER_KEY_HERE
EOF
```

## Сценарий запуска

1. Проверь порт `8080`:

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN
```

2. Если порт `8080` уже слушает Java/jasper_ai, второй экземпляр не запускай. Сообщи пользователю, что приложение уже доступно на `http://localhost:8080/`.

3. Если порт `8080` занят другим процессом, сообщи пользователю, что порт занят, и покажи найденный процесс.

4. Если `lsof` ничего не выводит, выполни детерминированные проверки:

```bash
./scripts/pre-start.sh
```

5. Если `pre-start.sh` завершился с ошибкой, примени раздел "Ошибки скриптов". `start.sh` не запускай и порт не жди.

6. Если `pre-start.sh` вернул `JASPERAI_PRE_START_STATUS=OK`, запускай Java-приложение:

```bash
mkdir -p ./logs
./scripts/start.sh > ./logs/start-command.log 2>&1 &
```

7. После запуска жди появления порта `8080` не дольше 15 секунд. Если `start.sh` уже вернул `JASPERAI_ERROR_RESOLVER`, прекращай ожидание:

```bash
for i in $(seq 1 15); do
  lsof -nP -iTCP:8080 -sTCP:LISTEN && break
  grep -q 'JASPERAI_ERROR_RESOLVER=' ./logs/start-command.log && break
  sleep 1
done
```

8. Если порт `8080` слушает Java/jasper_ai, сообщи пользователю, что приложение запущено, и дай адрес `http://localhost:8080/`.

9. Если порт `8080` не появился, проверь вывод команды запуска и хвост лога приложения:

```bash
cat ./logs/start-command.log
tail -n 80 ./logs/jasperai.log
```

10. Если `start-command.log` содержит `JASPERAI_ERROR_RESOLVER`, примени раздел "Ошибки скриптов".

11. Если структурированной ошибки нет, не печатай лог целиком. Сообщи пользователю, что приложение не подтвердило запуск, и кратко перескажи релевантные строки из вывода/хвоста лога.

## Сценарий остановки

```bash
./scripts/stop.sh
```

Если `stop.sh` завершился с ошибкой, примени раздел "Ошибки скриптов".

Если `stop.sh` вернул `JASPERAI_STOP_STATUS=NOT_RUNNING`, сообщи пользователю, что JasperAI не запущен.

Если `stop.sh` вернул `JASPERAI_STOP_STATUS=STOPPED`, сообщи пользователю, что JasperAI остановлен.
